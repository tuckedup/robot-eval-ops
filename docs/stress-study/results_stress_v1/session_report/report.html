RobotEvalOps evaluation report

Purpose

Report the outcome of a robot-policy evaluation: how many trials were planned, attempted and scored, what each controller achieved under each condition, how trials failed, and how complete the recorded evidence is. It states denominators and uncertainty; it does not claim more than the data supports.

Provenance

SIMULATION — PyBullet Panda arm with rendered simulator frames; not the SO-101 and not hardware

Provenance in this report: simulation. Controller types: scripted. Provenance (where data came from) and controller type (who produced actions) are separate fields.

Methods

  • Task rubric rubric-v1: block entirely inside the target region, released, and stays for the dwell time within the attempt timeout; any operator assistance prevents an autonomous success.
  • planned: all trials given (never-attempted trials stay here)
  • attempted: started_at set (reached RUNNING)
  • completed/failed/aborted: lifecycle state counts
  • unscored: attempted trials with task_outcome=unscored
  • evaluable: COMPLETED, scored success|failure, recording_quality in {pass, flagged}; unchecked/error/fail are excluded and counted in quality_excluded
  • raw_task_successes: COMPLETED + scored success regardless of QA or intervention (unverified)
  • success_per_attempt: VERIFIED autonomous successes (QA pass|flagged) / attempted
  • success_per_evaluable: VERIFIED autonomous successes / evaluable
  • intervention_rate: intervention == assisted / attempted
  • infra_abort_rate: attempted trials terminated by an infra reason / attempted
  • recording_pass_rate: recording_quality == pass / attempted
  • artifact_completeness: present+hash-recorded / expected (expected includes video+trace per attempt)
  • checksum_agreement: verified / transferred (uploaded+verified+mismatch)
  • Wilson 95% intervals on every rate. Durations: recorded values only (mean/median/min/max with n); nothing imputed.
  • Pairing: the same seed per (condition, trial index) across controllers; paired comparison lists discordant pairs and an exact McNemar p-value, which does not support significance claims at this n.

Limitations

  • The controllers evaluated by this repository are scripted, state-based programs reading simulator state; they are not learned policies and not trained checkpoints.
  • Simulation results use a PyBullet Panda arm with rendered simulator frames. This is not the SO-101 arm and not physical hardware; no conclusion about real-robot performance follows.
  • Mock-provenance results are seeded fixtures and are never evidence of robotics performance.
  • Visual-only conditions (lighting, background, occlusion) do not change what a state-based controller reads; they say nothing about the visual robustness of a learned policy.
  • Small sample sizes: Wilson intervals are wide and any difference between controllers is descriptive. p-values from so few discordant pairs do not support significance claims.
  • Scoring agreement between independent human scorers and reset-time improvements are not measured by this report; they need independent human measurement (see docs/evaluation-protocol.md).
